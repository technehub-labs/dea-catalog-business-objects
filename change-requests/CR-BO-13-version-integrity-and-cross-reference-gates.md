## 1. Purpose

The catalog had no version discipline that CI can enforce: all 58 records
sat frozen at `version: 1.0.0` regardless of edits, nothing connected record
changes to version bumps, and nothing detected when a sibling-catalog change
(ECF coordinates, capability/process ids) invalidated a reference. This CR
lands the version ledger, the two gates that enforce it, and the policy
document.

## 2. Changes

### 2.1 Version manifest (`reconciliation/version-manifest.yaml`)

Generated by `scripts/version_manifest.py generate` — never hand-edited. Per
record: version, substance content hash (SHA-256/16 over the record minus
`version`, `provenance`, `state_history`, `metadata`), file path; plus the
catalog-level version (`0.1.0` until the first release cut). 58 records
pinned at generation.

### 2.2 Version Integrity gate (VER-001..003, blocking)

- **VER-001 — coverage:** every record in the manifest, no phantoms;
  admissions and removals must update the manifest in the same CR.
- **VER-002 — coherence:** substance hash changed ⇒ record version must
  bump; version bumped ⇒ substance must have changed. Both violation
  directions are detected.
- **VER-003 — catalog version:** present and SemVer-shaped.

### 2.3 Cross-Reference gate (XREF-001..002, blocking)

CI clones `dea-catalog-business-capabilities` and
`dea-catalog-business-processes` at HEAD and verifies every
`capabilities_consumed[]` / `processes_involved[]` reference resolves.
Sibling drift now fails **in this repo's CI**, at the consumer — previously
only the local admission-time check existed (CR-BO-05 §2.2's discipline),
with no CI enforcement.

### 2.4 Policy + workflow

- `docs/versioning.md`: record-version trigger table, catalog-version (release
  cut) trigger table, manifest contract, gate descriptions, release-cut
  procedure, prior-cut history.
- `.github/workflows/validate-versioning.yml`: both gates on every PR and
  push to main.
- `tests/test_version_manifest.py`: unit tests for both gates, including
  both VER-002 violation directions.

## 3. Acceptance criteria (verified locally)

- AC-01 Manifest generates for all 58 records; catalog version `0.1.0`.
- AC-02 `check-version-integrity --strict` → CONFORMANT on the committed tree.
- AC-03 Substance tampering without a version bump → VER-002 finding (tested).
- AC-04 Version bump without a substance change → VER-002 finding (tested).
- AC-05 Manifest record removal → VER-001 finding (tested).
- AC-06 `check-cross-references` against sibling HEADs → CONFORMANT, 153
  references, 0 findings (tested).
- AC-07 Broken reference → XREF-001/002 finding (tested).
- AC-08 Test suite passes; no existing gate regressed (IDM, ES, AUT, catalog
  index all CONFORMANT).

## 4. Out of scope

- Automatic tag cutting (release cuts remain governed manual events per the
  policy document).
- Sibling content-change tracking beyond id existence (governed by the
  metamodel ECF conformance chain).
- Record-docs (README/aspects) versioning.
